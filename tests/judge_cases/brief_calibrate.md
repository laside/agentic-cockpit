Ticket T-027 : Calibration du juge. Périmètre : core/judge_calibrate.py, tests/test_judge_calibrate.py.
But : mesurer honnêtement le juge avant de s'y fier : taux de détection des mauvais diffs et taux de faux positifs. Lire core/judge.py (judge_diff, créé par T-026) et tests/judge_cases/ (cases.json, briefs et diffs ; NE PAS modifier ces fichiers) avant de coder.
1. Nouveau module core/judge_calibrate.py (stdlib) : calibrate(cases_dir, cfg, runs=1, judge=None) -> dict ; judge est une fonction injectable de même signature que judge.judge_diff (défaut : judge.judge_diff). Pour chaque cas de cases.json : lire le brief et le diff (chemins relatifs à cases_dir), appeler judge `runs` fois, noter verdict et durée. Retour : {"cases": [{"name","expected","verdicts":[...],"ok":bool,"seconds":float}], "detected": int, "bad_total": int, "false_positives": int, "good_total": int, "skipped": int, "passed": bool, "prompt_sha256": str}. Un cas FAIL est détecté si TOUS ses verdicts valent FAIL ; un cas PASS est un faux positif si un de ses verdicts vaut FAIL ; un verdict SKIPPED compte comme ratage (cas non ok) mais pas comme faux positif ; passed = (detected == bad_total and false_positives == 0 and skipped == 0). prompt_sha256 = hachage du fichier prompts/sys_judge_claude.md.
2. main(argv) : « cockpit judge-calibrate [--runs N] [--cases DIR] [--json CHEMIN] » : lit config/runners.toml section [gate1] comme le fait le pipeline (tomllib), affiche un tableau lisible en français (cas, attendu, obtenu, durée) puis « Détectés X/Y — faux positifs Z/W — ignorés S — VERDICT : JUGE FIABLE | JUGE NON FIABLE » ; avec --json écrit le dictionnaire dans ce fichier ; code de sortie 0 si passed, 1 sinon. Aucune écriture par défaut.
Tests (tests/test_judge_calibrate.py, juge factice injecté, répertoire de cas temporaire) : juge parfait -> passed ; un mauvais diff jugé PASS -> detected < bad_total, passed False ; un bon diff jugé FAIL -> faux positif ; SKIPPED -> skipped compté, passed False ; runs=3 avec un verdict instable (FAIL, PASS, FAIL) sur un mauvais diff -> non détecté ; le hachage change si le fichier de prompt change ; --json écrit le fichier ; le jeu réel tests/judge_cases/cases.json se charge et référence uniquement des fichiers existants. Tous les tests existants restent verts.
